Problem Formulation & Scope

Research Question

Can we accurately detect phishing URLs at click-time using strictly lexical features extracted from the raw URL string ("zero-packet" detection), and how much do pre-computed dataset columns in public benchmarks artificially inflate model performance through feature leakage?

Unit of Analysis

One individual URL string. Each row in our dataset is a single URL to be classified.

Target Definition

Binary classification: is_phishing = 1 (Phishing, positive class) and is_phishing = 0 (Legitimate, negative class). We inverted the raw UCI labels (where 1 = Legitimate and 0 = Phishing) so that Recall directly measures Phishing Detection Rate and FPR measures the fraction of safe legitimate URLs wrongly blocked.

⚡ The "Zero-Packet" Constraint

When a user clicks or hovers over a link, a client-side browser filter only sees the raw URL string. Fetching the HTML DOM, executing JavaScript, following HTTP redirects, or querying remote WHOIS/similarity databases introduces network latency (hundreds of milliseconds to seconds) and exposes the user's IP address to the attacker's server.

Therefore, any feature requiring network packets or external database lookups is strictly forbidden at inference time.

Limits of the Claim

A pure URL-only model evaluates lexical structure, not page intent. It cannot see credential-harvesting forms hosted on compromised legitimate domains or clean subdomains on free developer hosting platforms (e.g., Replit, Pantheon, Firebase). These cases are analyzed in our error analysis (Section 6).

Why URLSimilarityIndex is Leakage

Computing a similarity index requires comparing a candidate URL against a master reference list of known legitimate/target domains curated during dataset construction. At click-time in the wild, a browser does not have an oracle reference score pre-computed against the test set's target distribution.

Thus, we ban both columns from all subsequent modeling.

Metrics Justification

⚠️ Accuracy alone is misleading in security tasks because operational costs are highly asymmetric.

False Positive (FP) — Blocking Legitimate Traffic

Blocks a user from visiting a legitimate website, causing immediate user frustration and filter disablement. Hence, False Positive Rate $\text{FPR} = \frac{\text{FP}}{\text{FP} + \text{TN}}$ and Precision are critical.

False Negative (FN) — Missing Phishing Attacks

Lets a phishing attack slip through to the user. Hence, Recall (TPR) $= \frac{\text{TP}}{\text{TP} + \text{FN}}$, F1-Score, and threshold-independent ROC-AUC are reported.

Limitations & Risks

Free Cloud / PaaS Subdomain Blindspot

Attackers hosting phishing kits on legitimate cloud platforms (repl.co, pantheonsite.io, github.io, vercel.app) inherit clean domain structures and valid HTTPS certificates.

Lack of Character Entropy / N-gram Modeling

Random gibberish domains (smcbacmzu.icu) pass basic length/digit checks if they contain only lowercase letters; adding Shannon entropy or character bigram probabilities would help catch these.

Dataset Construction Bias

In PhiUSIIL, legitimate URLs are predominantly root domains with https://www., while many phishing URLs have long paths or missing HTTPS. A model trained on this benchmark can over-rely on uses_https and path_len_ratio unless verified on external traffic.

7

Conclusion

🛡️

Zero-Packet Features Are Highly Effective

With 0.9969 ROC-AUC using Random Forest and 1.55s extraction for 235k URLs, lexical URL features provide a fast first line of defense before any network packet is sent. At the tuned threshold, the model catches 99.33% of phishing URLs while blocking only 0.92% of legitimate traffic.

🔍

Benchmark Auditing Is Mandatory

Public cybersecurity datasets can harbor severe feature leakage: URLSimilarityIndex achieves 0.9961 AUC alone, distorting published leaderboard claims. Any research using PhiUSIIL without excluding these columns reports inflated results.

⚙️

Threshold Calibration Bridges ML & Deployment

Tuning the decision threshold on a validation set allows operators to explicitly cap false alarms ($\text{FPR} = 0.92\%$) while retaining 99.33% phishing recall. This transforms a raw ML model into a deployable security filter with guaranteed operational constraints.

13-Feature Zero-Packet Extractor Function

import re from urllib.parse import urlparse SUSPICIOUS_TOKENS = ['login', 'verify', 'secure', 'account', 'update', 'signin', 'banking', 'confirm'] IP_REGEX = re.compile(r'^(?:\d{1,3}\.){3}\d{1,3}$') def extract_single_url_features(url_str): url_str = str(url_str).strip() if not (url_str.startswith('http://') or url_str.startswith('https://')): parsed = urlparse('http://' + url_str) uses_https = 0 else: parsed = urlparse(url_str) uses_https = 1 if parsed.scheme.lower() == 'https' else 0 hostname = parsed.hostname or '' path = parsed.path or '' url_length = len(url_str) hostname_length = len(hostname) dot_count = url_str.count('.') hyphen_count = hostname.count('-') digit_count = sum(c.isdigit() for c in url_str) digit_ratio = digit_count / url_length if url_length > 0 else 0.0 special_symbols = sum(url_str.count(s) for s in ['@','?','=','&','%']) host_parts = hostname.split('.') subdomain_count = max(0, len(host_parts) - 2) if len(host_parts) > 2 else 0 host_is_ip = 1 if IP_REGEX.match(hostname) else 0 url_lower = url_str.lower() suspicious_words = sum(1 for kw in SUSPICIOUS_TOKENS if kw in url_lower) path_len_ratio = len(path) / url_length if url_length > 0 else 0.0 tld = host_parts[-1] if len(host_parts) >= 2 else '' tld_length = len(tld) return [url_length, hostname_length, dot_count, hyphen_count, digit_count, digit_ratio, special_symbols, subdomain_count, uses_https, host_is_ip, suspicious_words, path_len_ratio, tld_length]

from sklearn.preprocessing import StandardScaler from sklearn.ensemble import RandomForestClassifier from sklearn.metrics import roc_curve import numpy as np # Fit scaler on train only (for Logistic Regression) scaler = StandardScaler() X_train_scaled = scaler.fit_transform(X_train) X_val_scaled = scaler.transform(X_val) X_test_scaled = scaler.transform(X_test) # Train Random Forest (tree models use unscaled features) rf = RandomForestClassifier(random_state=42) rf.fit(X_train, y_train) # Threshold tuning on validation set: maximize Recall s.t. FPR ≤ 1% val_probs = rf.predict_proba(X_val)[:, 1] fpr, tpr, thresholds = roc_curve(y_val, val_probs) valid_idx = np.where(fpr <= 0.01)[0] best_idx = valid_idx[np.argmax(tpr[valid_idx])] tuned_threshold = thresholds[best_idx] print(f"Tuned τ = {tuned_threshold:.4f}") # 0.0809
